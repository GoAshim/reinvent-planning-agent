# re:Invent 2026 Planning Agent

An AI agent that helps plan an AWS re:Invent 2026 schedule. It searches sessions, looks up session details and checks for time conflicts, using Claude Haiku 4.5 on Amazon Bedrock and a local SQLite database of 1,099 sessions.

The agent is built two ways, to compare the approaches:

1. **Hand-built agent loop**: written directly against the Bedrock Converse API.
2. **Strands agent**: built with [Strands Agents](https://strandsagents.com), with SQLite short-term and long-term memory, and tracing in [Arize Phoenix](https://phoenix.arize.com).

```
  agent_cases.json        Evaluation cases
  eval_agent.py           Evaluation runner
```

## Architecture

### 1. Hand-built agent loop

![Hand-built agent loop: a test script calls run_agent_loop, which calls Bedrock Converse, reads stopReason, and runs tools through tool_dispatcher.py and tools.py against sessions.db, up to 5 iterations](docs/images/manual-agent-architecture.svg)

Every step is my own code: building the message list, calling Converse, reading `stopReason`, dispatching tools and sending their results back. Tool schemas are written by hand as JSON. The loop stops on `end_turn`, raises an error on `max_tokens`, and gives up after 5 iterations. It has no memory: every call starts fresh.

### 2. Strands agent with memory and tracing

![Strands agent: run_strands_agent_with_LTM loads history and preferences from memory.db, runs the Strands event loop against Bedrock and strands_tools.py, saves the turn, and sends OpenTelemetry spans to Phoenix](docs/images/strands-agent-architecture.svg)

The code prepares the context and saves the result; Strands runs the loop. Tool schemas are generated from type hints and docstrings. Memory is two SQLite tables:

- **Short-term** (`messages`): the conversation for one `session_id`, passed to the agent as its starting messages.
- **Long-term** (`user_preferences`): preferences per `user_id`, such as a preferred level or a venue to avoid. They are added to the system prompt, and the agent saves new ones with a `save_user_preference` tool. That tool gets `user_id` from the code, never from the model.

Strands sends its own OpenTelemetry spans for each agent run, loop cycle, model call and tool call. The only setup is one `register()` call from `phoenix.otel`.

## Comparison

**What's the same:** the model (Claude Haiku 4.5 on Bedrock), the three tools and their SQLite queries, and the AWS profile.

| | Hand-built loop | Strands agent |
|---|---|---|
| Agent loop | `for` loop and `stopReason` checks | Strands event loop |
| Tool schemas | Hand-written JSON | Generated by `@tool` from type hints and docstrings |
| Tool dispatch | `execute_tool` if/elif | Automatic, by tool name |
| Tool errors | returns `status: "error"` | Handled by Strands |
| Memory | None | SQLite short-term and long-term memory |
| Tracing | Needs `BedrockInstrumentor` plus it's own spans | Built in, one `register()` call |
| Lines of agent code | More, all visible | Less, the loop is hidden |

**Highlights:**

- **The hand-built loop shows how agents work.** Tool use is just a loop: call the model, run the tools it asks for, send the results back, repeat.
- **Strands removes the repetitive work**, but missing type hints on a tool still lead to a schema with no types, and to bad tool calls.
- **Tool results must be JSON objects.** Bedrock rejects a bare list or `None`, so lists are wrapped as `{"sessions": [...]}` and missing sessions return `{"error": ...}`.
- **All SQL is parameterized**, so tool inputs from the model cannot inject SQL.
- **Long-term memory is keyed by values the model never controls** (`user_id`), so one user cannot write to another user's preferences.

## Running

Each script runs from the project root as a module:

```powershell
python -m tests.test_multi_tool_agent      # hand-built loop
python -m tests.test_strand_agent          # Strands agent, short-term memory
python -m tests.test_long_term_memory      # Strands agent, long-term memory
python -m tests.inspect_sqlite_memory      # print saved conversation rows
```

### Tracing

Start Phoenix in a separate terminal, run any Strands test, then open http://localhost:6006 and select the `reinvent-agent-local` project.

```powershell
phoenix serve
python -m tests.test_phoenix_tracing
```

### Evaluation

`tests/eval_agent.py` runs every case in `tests/agent_cases.json` and scores the answers with code checks. These include which tools were called, whether every session ID in the answer exists, and whether the sessions match the requested level, day, type and keyword.

```powershell
python -m tests.eval_agent            # every case, once
python -m tests.eval_agent 3          # every case, 3 runs each
python -m tests.eval_agent 3 002 007  # selected cases
```

Answers and tool calls are saved to `tests/eval_results.json`.
